## Owner's deployment and governance sources

At the owner's follow-up direction, the connected GitHub account was used to inspect `nandahtoon/Mifosx-web-app`, `nandahtoon/MicroOps-Infra`, and `nandahtoon/MicroOps-360-Fineract-Org`. No changes were made in those repositories. See ORACLE-STAGING.md for exact source paths, live public provenance and the authenticated-access limitation.

The 20.0.8.0.0 declarations in scripts/admin_contracts.py use the same owner revision's edit-standing-instructions, create/edit-loan-provisioning-criteria, create-dividend, view-dividend and manage-scheduler-jobs components, plus their account-transfers, organization, products and system services. Fineract corroboration at the Apache revision above includes fineract-account-transfer/.../StandingInstructionUpdateRequest.java and StandingInstructionApiResource.java, and provider organisation/provisioning/serialization/ProvisioningCriteriaDefinitionJsonDeserializer.java, portfolio/shareproducts/api/ShareDividendApiResource.java and ShareProductWritePlatformServiceJpaRepositoryImpl.java. These establish field bounds, category/product projections, command separation, dividend subresource references and approval-body normalization. Calculation code remains exclusively in Fineract.

Version 20.0.9.0.0 uses the pinned owner bulk-loan-reassignmnet and view-holidays components and savings-account-view toggle handlers. Source links in scripts/organization_contracts.py include primary Fineract BulkLoansApiResource, HolidaysApiResource and SavingsAccountsApiResource references. The corresponding write services verify remote officer ownership, assignment dates and savings tax applicability. Scheduler reconciliation was checked against infrastructure/jobs/api/SchedulerApiResource.java: start/stop returns an empty 202 and the status read has only active, with no resource identifier.

Remote maker-checker identity research at the Apache revision above used [MakercheckersApiResource](https://github.com/apache/fineract/blob/6a28754c6839fa64f5faf1873f9fcb52bc330fd9/fineract-provider/src/main/java/org/apache/fineract/commands/api/MakercheckersApiResource.java), [PortfolioCommandSourceWritePlatformServiceImpl](https://github.com/apache/fineract/blob/6a28754c6839fa64f5faf1873f9fcb52bc330fd9/fineract-core/src/main/java/org/apache/fineract/commands/service/PortfolioCommandSourceWritePlatformServiceImpl.java), [AppUser permission checks](https://github.com/apache/fineract/blob/6a28754c6839fa64f5faf1873f9fcb52bc330fd9/fineract-core/src/main/java/org/apache/fineract/useradministration/domain/AppUser.java) and [AuthenticationApiResource](https://github.com/apache/fineract/blob/6a28754c6839fa64f5faf1873f9fcb52bc330fd9/fineract-security/src/main/java/org/apache/fineract/infrastructure/security/api/AuthenticationApiResource.java). AuditData returns maker/checker usernames rather than numeric IDs; makerId-filtered pending audits and the scoped user lookup can bind original maker identity. Basic authentication POST returns the authenticated ID but also sensitive authentication material, which any future identity adapter must discard in memory without persistence or logging. GET /users/{id} does not prove the caller's identity. No such authentication call or remote decision was performed here.

AuditData.commandAsJson and AuditReadPlatformServiceImpl's direct aud.command_as_json selection motivated the audit metadata projection. The native adapter retains declared scalar audit evidence, excludes submitted payloads and unneeded URLs/IPs, and bounds row/text sizes before persisting read results. This projection is independently authored; no upstream Java implementation is copied.
